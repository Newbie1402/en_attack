# 05 — Engineering, coding and security rules

- TS strict, `noUncheckedIndexedAccess`, consistent ESLint/Prettier; explicit public return types, discriminated unions and exhaustive switches; no `any`, unsafe casts, non-null assertions used to mask bugs, or suppressed checks without documented justification. Prefer simple functions and modules over needless patterns. English identifiers, concise comments explain why. React functional components/hooks; avoid oversized components, use feature hooks, clean effects and event listeners. Keep domain/application independent of frameworks and IO. Do not create generic abstraction before use case.
- One authoritative state, typed commands/events, deterministic clock/RNG, no hidden mutation from UI. Atomic check-then-apply commands; rejection changes no resources, quota, timers or effect stock. Config-driven tuning; no magic numbers in logic. Document units (cells, ticks, seconds) and rounding. Fixed-step deterministic, no date/time in gameplay logic; avoid UI read-model modifying game. Use typed error codes; display localized explanations; recover from malformed data without crash.
- Treat formula, save, route params, configs as untrusted. Follow 02 parser/AST allowlist, resource bounds, manual evaluator; no arbitrary JS, eval, compilation or unsafe math.js functions. Reject parser bombs before parsing, bound sampling and comparisons, return typed errors. No HTML injection / dangerouslySetInnerHTML for expressions; React escaping, Canvas plain text. No remote assets/scripts, no inline runtime JS where avoidable. LocalStorage only non-sensitive settings and progress, bounded schema and migrations. No backend/auth/CSRF surface in static MVP; if server later requested, separately design authentication, authorization, CSRF, validation and rate limits. Never introduce secrets into client. Do not disable CSP or enable unsafe-eval to make library work; verify production console. Audit dependencies and document high severity findings, don't blindly upgrade majors. No service worker initially.
- Performance: one RAF owner; precompute/cap trajectories, collision swept, bounded entities and particles, no unbounded timers or histories. Avoid allocations inside hot loops when measured; texture atlases, lazy route/theme loading, pool sprites/particles if needed. No per-frame Zustand updates. Dispose game and audio on route exit; StrictMode safe, no duplicate canvas/listeners. Browser visibility pause; audio unlocked by gesture.
- Git: inspect status, preserve unrelated work; no reset --hard, clean, commit/push, deployment without permission. Record tool limitations. Verify lockfile with npm ci, no unpinned runtime CDN. Keep README commands accurate. Do not expose unsupported feature buttons; mark future content locked/coming soon. Test real behavior rather than snapshots alone. Update progress and decisions after every phase.
