| D17 | Store only a bounded version-1 campaign/settings object in localStorage and recover invalid data to defaults | The MVP has no backend; Zod parsing prevents malformed or future data from crashing the app, and winning a level unlocks only its immediate successor |
| D18 | Sandbox previews call the same validator and sampler as combat but never write campaign progress | This keeps the formula contract singular while preserving the campaign as the only progression surface |
| D19 | Keep procedural/vector art as a documented placeholder until Phase 08 asset and manual visual gates | It is real local rendering and preserves the approved silhouette/palette, but the supplied concept images are references, not production sprite sheets or backgrounds |
| D20 | Give gameplay its own fixed desktop viewport and keep the website shell off the play route | The brief prioritizes battlefield visibility and no-scroll control access; mobile falls back to a normal document flow so touch layouts remain usable |
| D21 | Load original local SVG art in Phaser while keeping simulation data and animation ownership separate | Independent textures replace the primitive runtime character path; simulation events may trigger cosmetic tweens, but never rewards, damage, projectiles or progression |
| D22 | Resolve pickup pointer hits before unit selection when both occupy the same cell | A collectible is the higher-intent visible affordance; this prevents the nest underneath from intercepting a valid collection click and is covered by the browser pickup test |
| D23 | Store one assigned formula per combat unit in serializable simulation state and derive level-scoped ownership from units; keep usage history in the quota registry | V3 requires independent reusable formulas without coupling ownership to historical usage. Reassignment is atomic and behaviorally equivalent formulas conflict before state changes. Verified by `v3.test.ts`. |
| D24 | Schedule attacks inside the fixed-step simulation after wave/production updates; React and Phaser only consume snapshots and send placement/editor commands | This removes the manual Fire loop while preserving deterministic projectile paths, cooldowns and quota enforcement. A compatibility `fire` command remains for old callers but is not exposed by the V3 HUD. |
| D25 | Make shop selection enter explicit tile placement and charge relocation separately with a small cost/cooldown | Player intent is visible before a unit mutates the board, and relocation cannot become a free reposition exploit. Invalid placement leaves simulation state unchanged. |
| D26 | Model enemy defense as shield → armor → health, with per-kind freeze resistance and facing reduction | The pipeline supports tactical counterplay without embedding enemy-specific damage branches in the renderer. Turtle, boar and wolf behavior are covered by deterministic tests; balance remains tunable. |
| D27 | Upgrade `react-router-dom` from 6.30.1 to 6.30.6 before V3 commit; defer the remaining React Router 7-only audit fixes | The patch removes the 3 high advisories without a major migration. `npm audit --omit=dev` now reports 2 moderate advisories whose suggested fix is React Router 7 and therefore requires a separate compatibility task. |
| D28 | Keep a typed runtime-ready asset subset in `src/presentation/assets/assetManifest.ts` and a richer status inventory in `public/assets/manifests/` | Phaser must never request pending files, while production tooling still needs to see planned assets and blockers. `npm run assets:check` validates ids and present local files. |
| D29 | Treat generated Pack 01 art as visual-development evidence only until it has transparent frames, pivots, hitboxes and manifest integration | Image generation is useful for style iteration, but a contact sheet is not a runtime sprite atlas and must not be mislabeled as one. |
| D30 | Record the Pack 01 art handoff as an external-authoring candidate and keep the existing SVG runtime fallback until the individual PNG frames arrive | The handoff and contact sheet are now preserved as evidence, but no per-pose PNGs or verified atlas files were transferred into the repository. This prevents a broken preload path and keeps the simulation/render boundary intact. |
