# 06 — Implementation roadmap (mandatory gates)

Each phase: inspect prior artifacts, list planned edits, implement, verify and fix, record evidence in 08, then advance. Inputs include referenced specs and earlier passing gates. Outputs must exist as working source/tests/docs, not prose or placeholder TODOs. All gates require no regressions and actual command evidence; report BLOCKED if tools/assets unavailable. Use `npm test` for non-watch Vitest and `npm run test:e2e -- <pattern>` for targeted Playwright. `npm run verify` = lint + format:check + typecheck + test + build; E2E separately (browser setup documented). Phase order below intentionally introduces art contracts before final artwork so gameplay can be tested early.

## Phase 00 — Foundation
**Input:** kit, empty/existing repo, reference PNGs. **Implementation:** inspect git, resolve tooling versions using official package metadata, scaffold Vite React TS, Phaser lifecycle smoke, Tailwind, Router, Zustand, Zod, ESLint, Prettier, Vitest, Playwright; add scripts and lockfile, basic CI and README; directory boundaries and design tokens. No artificial service/backend. **Output:** app boots, route skeleton, smoke test, package-lock, decisions version record. **Verify:** `npm ci`; `npm run verify`; `npm run test:e2e -- smoke`; open browser. **Exit:** one canvas at most, route smoke, no TS/lint/build errors, no unrelated file overwrite.

## Phase 01 — Mathematical engine
**Input:** 02, foundation. **Implementation:** normalize grammar, reject malicious/complex syntax preparse, allowlisted AST -> immutable IR, safe finite evaluator, domain/origin validation, adaptive sampler + conservative interval validation, canonical key and behavioral matching, typed errors. **Output:** pure TS API, test fixtures for all supported functions, quotas registry (counts integrated later). **Verify:** `npm test -- math`; `npm run verify`. **Exit:** equivalent aliases share bucket; valid formulas/invalid input cases pass, no bridging singularities, no JS execution, budget deterministic; explicit unsupported cases explained. Do not advance if sampler lies about discontinuity handling.

## Phase 02 — Simulation, board and collision
**Input:** Phase 01, 01/02/03. **Implementation:** world<->screen transform, square cells, fixed tick session, command result/events, deterministic RNG, occupancy, moving targets, sampled trajectory advancement, swept collision, hit order/armor/obstacles, entity caps, lifecycle, seed replay. **Output:** headless simulation with deterministic fixtures and interpolation contract. **Verify:** `npm test -- simulation`; `npm test -- collision`; `npm run verify`. **Exit:** x=y visual angle invariant at resize, no tunneling, no duplicate hit, same seed/commands same state, pause stops ticks, breach resolution deterministic.

## Phase 03 — Playable vertical slice
**Input:** Phase 02, art direction, temporary original assets. **Implementation:** Phaser battlefield and React HUD/editor bridge, 10x5 natural tiles, place initial basic bird, select, hover local coords, formula input/inline validation/preview, fire, animated snowball and target hit. Simple 1-wave test level and retry; no campaign axes. **Output:** playable browser prototype. **Verify:** `npm run test:e2e -- gameplay`; `npm run verify`; capture 1440x900 and 1280x720 screenshots. **Exit:** user can win/lose/retry, formula trajectory actually hits moving targets, preview matches shot, no fixed axes, resize/route disposal verified; no screenshot used as board.

## Phase 04 — Resource and economy
**Input:** vertical slice and balance config. **Implementation:** buy all MVP unit types, placement restrictions, costs, cooldowns, move mode, nest timers and deterministic spawn, pickup lifecycle, cap/expiry/collection, first-pass pop/bounce/collect-to-HUD animations. **Output:** functional shop and nest economy, effects events; fixtures for capacity. **Verify:** `npm test -- economy`; `npm run test:e2e -- economy`; `npm run verify`. **Exit:** invalid buy/move no charge, stock credited once on collect, full/expired pickup behavior correct, pause timers frozen, relocate does not change active flight, no instant-credit shortcut.

## Phase 05 — Tactical skills
**Input:** economy, 01 effects and 10 tuning. **Implementation:** Slow/Freeze with exact tick semantics, Double Damage pending shot, Formula Reset selection contract, skill HUD stock and active timers, seeded drop distribution/pity, first-pass effect animations/audio cues. Use quota registry harness for reset before boss integration. **Output:** 4 functional skills, tactical loop. **Verify:** `npm test -- skills`; `npm run test:e2e -- skills`; `npm run verify`. **Exit:** slow 0.4 and freeze 0 only affect enemies; skill timers continue while running; freeze/slow overlap correct; rejected fire retains armed boost; reset scoped and no stock loss on invalid action; drops visibly collectable.

## Phase 06 — Enemies and waves
**Input:** 02–05, enemy/level schema. **Implementation:** fox/boar/raven behaviors, telegraph lane switch, wave scheduler, spawn caps, wave HUD, base hearts, victory/defeat, intro/tutorial triggers. Test scripted waves and malformed configs. **Output:** playable authored regular levels L1–L4 with deterministic fixture solutions; retry/result screens. **Verify:** `npm test -- waves`; `npm run test:e2e -- waves`; `npm run verify`. **Exit:** all four regular levels winnable and loss possible, wave transitions and breach correctly tracked, no softlocks on cap/deferred spawn, tutorial can skip.

## Phase 07 — Boss and formula restrictions
**Input:** 01/02 quota rules, skills, wave engine. **Implementation:** level-wide usage per bucket, exact cap 3 default, optional family caps, shared quota across birds/moves, boss threshold transitions/telegraph adds/obstacles, preview restrictions, reset pickup pity and picker. Include L5 and L6 actual configured levels. **Output:** boss encounter and quota UI with fixtures; deterministic boss win/loss. **Verify:** `npm test -- quota`; `npm test -- boss`; `npm run test:e2e -- boss`; `npm run verify`. **Exit:** three accepted equivalent uses lock fourth, miss counts, rejection no state charge, reset unlocks only chosen bucket, thresholds fire once even large hit, preview policy enforced, authored strategy beats both levels without debug cheats.

## Phase 08 — Visual quality, animation, audio
**Input:** approved PNGs, 04/11, gameplay events, passing game. **Implementation:** create coherent original mascot-inspired sprite variants, enemies, nest, tiles, seasonal background layers, icons/UI, sound with provenance; animation states, asset manifest, effects and reduced-motion; spring/winter theme swap. Visual polish must be implemented not just described. **Output:** runtime sprite sheets/atlases, local audio, screenshots before/after, art manifest. **Verify:** `npm run verify`; `npm run test:e2e -- visual`; manual screenshot inspection at 1280x720, 1440x900, 1920x1080; inspect pickup sequence and damage animation via recording or frame captures. **Exit:** no axes, obvious grid cells, readable HUD, distinct birds, visibly animated drop cycle, asset sources documented; if no art tools, deliver original local placeholders and mark concept-fidelity gate BLOCKED rather than claim full visual approval. Do not let decorative work break controls.

## Phase 09 — Campaign, sandbox, settings
**Input:** six playable level configs, art assets, save schema. **Implementation:** main menu, world map, unlock progression, bestiary, sandbox sharing engine, settings (vi/en, audio, motion, hints), versioned local save/migrations, corrupt recovery, accessible focus/touch. Author six levels; future chapter nodes marked planned, not playable. **Output:** cohesive six-level campaign, Sandbox Lab, persistent settings/progress, controls documentation. **Verify:** `npm test -- save`; `npm run test:e2e -- campaign`; `npm run test:e2e -- sandbox`; `npm run verify`. **Exit:** win unlocks next, reload keeps progress/settings, replay works, sandbox no progression side effects, invalid routes and corrupt save recover, no fake content.

## Phase 10 — QA, accessibility, performance, security
**Input:** integrated campaign. **Implementation:** regression checklist 07, full unit/integration/E2E, abuse fixtures, long-run stress, resize/motion/keyboard checks, dependency audit, production CSP smoke, actual profiling, fix regressions and record reproducible metrics. **Output:** `docs/qa-report.md`, screenshots, profiling logs/limitations, test evidence. **Verify:** clean `npm ci`; `npm run verify`; `npm run test:e2e`; audit and browser production build. **Exit:** all mandatory tests pass, six levels proven solvable by reproducible real-input fixtures, no known critical issue, no unbounded entity growth, security and accessibility acceptance met; no invented benchmarks.

## Phase 11 — Packaging and release candidate
**Input:** passing QA and asset license review. **Implementation:** multi-stage Dockerfile, non-root Nginx SPA on 8080, headers/cache/health, `.dockerignore`, CI verification, README instructions and troubleshooting. Keep references out of `dist`. No actual external deployment. **Output:** runnable dist/image recipe, release checklist, progress final status. **Verify:** `npm ci`; `npm run verify`; `npm run test:e2e`; `docker build -t snowgraph:local .`; run local container and curl health/root/deep-route; test browser with CSP. If Docker unavailable record exact blocker. **Exit:** local build, route fallback, static assets correct, non-root runtime, no secrets, deployment docs; claim release candidate only if required gates and brand/asset permissions for intended distribution satisfied.

## After MVP (separate approval)
Expand to 36 handcrafted levels, summer/autumn/sky/citadel tiles and mechanics, optional Free Move/Perfect Vision, difficulty presets, additional boss types. Balance and QA each content pack. No backend, multiplayer, analytics or paid items unless requested.
